# HeatShield AI - Judge Demo Script

Target: **5 minutes**, with a verified fallback if the live provider is slow.

## 0:00-0:20 - Problem

"Weather apps tell you how hot a city is. HeatShield AI tells you where heat becomes a priority, why, and what to do next."

State the distinction: FortyGuard provides verified hyperlocal temperature intelligence; HeatShield adds prioritization, provenance, controlled actions and a grounded assistant.

## 0:20-1:10 - Fresh live path

Open **Live Analysis**.

1. Keep the AOI small and use `100 m` granularity.
2. Run the fresh FortyGuard analysis.
3. Point out provider-backed thermal tiles, activity/provenance information and the top relative hottest tile.
4. If the request is slow or fails, immediately use the **Fallback** section below. Do not wait on stage and do not describe cached/historical evidence as current.

## 1:10-1:45 - Thermal-stress evidence

Enrich the hottest tile.

Show available Heat Index / Apparent Temperature / Wet-Bulb / Relative Humidity fields and the transparent hazard signal. Emphasize that planning priority remains withheld until operational context is verified.

## 1:45-2:30 - Verified context and priority

Use a pre-agreed authorized demonstration context reference such as `Supervisor-confirmed demo operations context`.

Verify exposure, operational vulnerability and protection/control factors. Show:

- evidence-adjusted planning priority;
- priority band;
- factor contributions;
- operational adjustment;
- provenance/source reference.

Say explicitly: "This is a transparent operational planning index, not a medical-risk probability."

## 2:30-3:20 - Grounded assistant

Open **Assistant** and ask:

> Why does the current live planning priority have this value?

Then ask:

> Where did this number come from?

Point out that local Qwen may route intent, but the final factual answer is deterministic and evidence-backed. Show evidence references and the medical-risk boundary.

## 3:20-4:15 - Scenario Studio

Open **Scenario Studio**. Choose one controlled preset and run the comparison.

Show:

- verified baseline;
- scenario estimate;
- delta in planning-priority points;
- explicit `ASSUMED` factor changes;
- thermal hazard held constant.

Say: "This is a scenario estimate. HeatShield is not inventing a degree-Celsius reduction or a measured future outcome."

## 4:15-4:40 - Evidence and controlled actions

Show the Evidence / provenance area and controlled recommendation status. Explain that actions come from a versioned catalog rather than unrestricted LLM invention.

## 4:40-5:00 - Close

"The same evidence-to-decision engine can support city planning, operations and other heat-sensitive workflows while keeping measurements, assumptions and recommendations traceable."

## Fallback - verified historical replay

If the live provider is slow, unavailable, or returns an unusable live response:

1. Click **Historical replay**.
2. State clearly that this is verified historical/scenario evidence, not current heat.
3. Show the thermal map and top hotspot.
4. Show temporal severity evidence and provenance.
5. Show the transparent planning score/factors.
6. Ask the grounded assistant why the hotspot ranks higher.
7. Show controlled action recommendations.
8. If time allows, return to Scenario Studio only if a verified live baseline is already present.

The fallback is the repeatability path; never fabricate a live completion.
