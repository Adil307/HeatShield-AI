# HeatShield AI - Judge Q&A

## What is actually AI?

HeatShield combines deterministic hotspot/risk/recommendation intelligence with a grounded conversational interface. Local Qwen can route intent, but verified tools and deterministic code remain the source of factual numbers.

## Why not use FortyGuard directly?

FortyGuard tells us what is happening thermally. HeatShield adds operational context, transparent priority, provenance, controlled actions, scenario comparison and a grounded user interface.

## Why trust the LLM?

We do not trust the LLM for measurements or final numeric claims. It can route intent; the factual response is rendered from verified evidence and checked by the Evidence Guard.

## Medical / scientific validation: is the planning score clinically validated?

No. It is a transparent, versioned prototype operational planning-priority index. It is not a clinically validated medical-risk probability.

## Where did this number come from?

Show the provider activity IDs, thermal/environmental evidence references, authorized operational context reference and planning-model version in the dashboard/assistant evidence panel.

## Are you inferring how many people are exposed?

No. A mapped object is not treated as a person or occupancy count. Exposure/operational context must be explicitly authorized or remains unknown.

## Why does Scenario Studio not predict a temperature reduction?

There is no validated site-specific cooling physics model in the MVP. Scenario Studio changes explicit operational assumptions and holds verified thermal hazard constant. A new time window requires fresh provider evidence.

## What if Premium FortyGuard features are unavailable?

The core product does not depend on Premium segmentation/report endpoints. The MVP works with Heatmap plus available Environmental Parameters.

## What if the API is slow during judging?

HeatShield uses asynchronous provider handling and caching. For the demo, we switch to the explicitly labeled verified historical replay instead of fabricating a live result.

## How do you control API credits?

Small AOIs, demo-safe granularity, deterministic request hashing, completed-response caching and selective hottest-tile enrichment.

## How is the assistant evaluated?

The final evaluation measures grounding pass rate, unsupported-claim rate, evidence-reference coverage, consistency, missing-data behavior, intent/tool-selection accuracy and local deterministic response latency.

## What is the main limitation?

A full live planning-priority comparison across multiple tiles requires equivalent environmental enrichment and authorized operational context for each tile. The current live flow intentionally enriches the selected hottest tile first.

## What would you build next after the hackathon?

Production persistence/authentication, multi-tile context workflows, validated intervention/physics models where authoritative data exists, deployment hardening, and broader evaluation with real operational users.
